# 블로그 제목 컨벤션

## 목적

제목은 태그를 반복하는 분류명이 아니라, 독자가 글에서 얻을 결과를 한 번에 전달한다. 분류는 front matter의 `tags`가 맡고 URL은 Markdown 파일명이 맡는다.

## 기본 형식

```text
독자가 얻는 결과
```

- 제목은 공백을 포함해 20자 이상 60자 이하로 쓴다.
- 한국어 문장 중심으로 쓴다. API, 제품명, 라이브러리, 표준처럼 정확한 검색어가 필요한 경우에만 원 표기를 유지한다.
- 제목은 결과를 말하는 한 문장으로 끝낸다. 기술 맥락, 제품명, 분류명을 꼬리표로 덧붙이지 않는다. 기술 맥락은 `tags`와 본문 첫 요약이 맡는다.
- 콜론(`:`)은 꼭 필요한 경우에만 하나 쓴다. 꼭 필요한 경우는 다음 둘뿐이다.
  - 같은 결과를 다른 기술로 설명한 글을 제목만으로 구분해야 할 때. 예: `LINQ Select로 데이터를 변환하는 방법: C#`
  - 시리즈 글. `시리즈명 N: 세부 주제`로 번호를 결과 영역에 둔다.
- 새 글에서 콜론 뒤에 쓸 말이 이미 제목 앞부분이나 `tags`에 있으면 지운다.

## 금지 표기

- `[C#]`, `[FE]`, `[Spring]`, `[Kubernetes]`처럼 태그와 중복되는 대괄호 접두어
- ` - `, ` + `, ` : `처럼 콜론 형식과 섞이는 구분자
- 콜론 두 개 이상
- `알아보자`, `해보자`, `작성해보자`처럼 독자의 행동을 권유하는 종결
- 같은 용어의 한글과 영문을 의미 없이 나열하는 표기
- 글의 주제어를 반복해 붙인 꼬리표. 예: `서비스 15개를 하루에 독립 저장소로 옮긴 기록: Peony 분리`

## 예시

| 이전 | 권장 |
| --- | --- |
| `[C#] LINQ 사용방법 - Select` | `LINQ Select로 데이터를 변환하는 방법: C#` (같은 주제의 다른 언어 글과 구분해야 할 때) |
| `[FE] webpack 에서 Source Map 이 동작하는 원리` | `Source Map으로 디버깅 위치를 찾는 원리` |
| `서비스 15개를 하루에 독립 저장소로 옮긴 기록: Peony 분리` | `서비스 15개를 하루에 독립 저장소로 옮긴 기록` |

기존 글의 `결과: 맥락` 제목은 일괄 변경하지 않는다. 글을 실질 개정할 때 위 기준으로 다시 본다.

## 자동 검증 경계

`site/scripts/Test-BlogTitleConvention.ps1`는 길이, 접두어, 콜론 개수(둘 이상 금지), 구분자, 권유형 종결, manifest 커버리지와 slug 입력 보존을 검사한다. 콜론이 꼭 필요한 경우인지, 독자 가치가 실제로 앞에 왔는지, 용어 선택이 자연스러운지는 자동 판정하지 않으며 manifest 리뷰에서 확인한다.
