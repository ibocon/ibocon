# 블로그 제목 컨벤션

## 목적

제목은 태그를 반복하는 분류명이 아니라, 독자가 글에서 얻을 결과와 그 기술 맥락을 한 번에 전달한다. 분류는 front matter의 `tags`가 맡고 URL은 Markdown 파일명이 맡는다.

## 기본 형식

```text
독자가 얻는 결과: 기술 맥락
```

- 제목은 공백을 포함해 20자 이상 60자 이하로 쓴다.
- 한국어 문장 중심으로 쓴다. API, 제품명, 라이브러리, 표준처럼 정확한 검색어가 필요한 경우에만 원 표기를 유지한다.
- 기본 제목은 콜론(`:`) 하나로 결과와 기술 맥락을 구분한다.
- 시리즈는 `시리즈명 N: 세부 주제`로 번호를 결과 영역에 둔다.

## 금지 표기

- `[C#]`, `[FE]`, `[Spring]`, `[Kubernetes]`처럼 태그와 중복되는 대괄호 접두어
- ` - `, ` + `, ` : `처럼 기본 콜론 형식과 섞이는 구분자
- `알아보자`, `해보자`, `작성해보자`처럼 독자의 행동을 권유하는 종결
- 같은 용어의 한글과 영문을 의미 없이 나열하는 표기

## 예시

| 이전 | 권장 |
| --- | --- |
| `[C#] LINQ 사용방법 - Select` | `LINQ Select로 데이터를 변환하는 방법: C#` |
| `[FE] webpack 에서 Source Map 이 동작하는 원리` | `Source Map으로 디버깅 위치를 찾는 원리: Webpack` |
| `[Spring] JPA Mapping - @ManyToMany` | `JPA 다대다 매핑의 한계와 대안: ManyToMany` |

## 자동 검증 경계

`site/scripts/Test-BlogTitleConvention.ps1`는 길이, 접두어, 구분자, 권유형 종결, manifest 커버리지와 slug 입력 보존을 검사한다. 독자 가치가 실제로 앞에 왔는지와 용어 선택이 자연스러운지는 자동 판정하지 않으며, manifest 리뷰에서 확인한다.
