---

## 2. 설계 원칙

### 2.1 번호 없는 목차 표기 (Number-Free TOC)

* ✅ **MUST** 목차 화면에 표기하는 모든 도메인 항목과 하위 상세 항목은 `01.`, `02.01.` 같은 번호 접두사 없이 도메인명·주제명만 표기한다.
* ⛔ **MUST NOT** 목차 표기를 위해 노션 사이드바의 실제 페이지 제목(`01. 소프트웨어 아키텍처` 등)을 번호 제거 형태로 개명하거나, 규약 문서의 2자리·4자리 명명 규칙을 폐기한다.

근거: 사이드바 번호는 페이지 정렬과 기존 링크 호환성을 담당하는 식별자이고, 목차 본문의 번호는 중복 표기에 불과하다. 표시 계층에서만 번호를 생략하면 두 목적을 모두 보존한다. 번호를 덜어내면 항목 폭이 짧아져 목차 각 줄이 1줄을 유지한다.

### 2.2 단일 책임 10대 도메인 유지

* ✅ **MUST** 목차의 도메인 항목은 기존 허브와 동일한 10개 단일 책임 도메인으로 유지하며, 두 개 이상의 직무 영역을 하나의 항목에 결합하지 않는다.
* ✅ **MUST** BLE·USB 하드웨어 연동은 시스템 프로그래밍 도메인에 유지하고, 모바일 도메인은 모바일 애플리케이션 단독으로 유지한다.
* ⛔ **MUST NOT** 목차 개편을 구실로 도메인 구조를 재편하거나 프로젝트 코드명 기반 최상위 분류로 되돌린다.

근거: [노션 이력서 정보 구조 및 작성 규약](./convention-notion-resume-structure.md) 제1규칙(Domain-First & SRP)과 제12규칙(이력서 탐색 목차)의 재확인이다. 이번 개편은 도메인 구조 개편이 아니라 목차 표기 개편이다.

### 2.3 Top-Down 배열 순서 고정

* ✅ **MUST** 목차는 추상 설계에서 시작해 저수준 시스템 영역에서 끝나는 아래 흐름의 순서를 유지한다.

```text
소프트웨어 아키텍처 (추상 설계 원칙)
  → .NET 백엔드 엔지니어링 (서버 구현)
  → 클라우드 및 온프레미스 인프라 (실행 기반)
  → DevOps 엔지니어링 (배포·운영)
  → 개발자 경험 (생산성 도구)
  → 하네스 엔지니어링 (AI 에이전트 계층)
  → 웹 디자인 시스템 (웹 클라이언트 공통 UI)
  → 모바일 애플리케이션 (모바일 클라이언트)
  → Windows 데스크톱 애플리케이션 (데스크톱 클라이언트)
  → 시스템 프로그래밍 (하드웨어 연동 저수준)
```

근거: 읽는 사람이 "설계 → 구현 → 실행 → 운영 → 생산성 → 클라이언트 → 하드웨어"의 한 방향 흐름으로 전체 역량 스펙트럼을 훑을 수 있게 하기 위함이다. 배열 순서 자체가 위계의 근거이므로 별도 번호가 필요하지 않다.

### 2.4 핵심 프로젝트 바로가기 병행

* ✅ **MUST** 탐색 목차는 도메인 색인에 앞서 경력에서 언급한 대표 프로젝트 바로가기(표시명·한 줄 역할·상세 링크)를 유지한다. 바로가기가 참조하는 상세 페이지 표기 역시 번호 없이 주제명만 표기한다.
* ⛔ **MUST NOT** 바로가기를 전체 문서 색인으로 확장하거나 도메인 색인과 역할을 중복시킨다.

근거: [노션 이력서 정보 구조 및 작성 규약](./convention-notion-resume-structure.md) 제11규칙에 따라, 자주 열람되는 대표 상세로의 진입 경로는 도메인 탐색과 별도로 가장 짧게 유지된다.

## 3. 전체 목차 (TOC)

> 표기 규칙: 도메인 항목과 하위 상세 항목 모두 번호 없이 주제명만 표기한다. 순서는 2.3의 Top-Down 흐름을 따른다.

```text
이력서 탐색 목차
│
├── 핵심 프로젝트 바로가기
│
├── 소프트웨어 아키텍처
│   ├── 계층 분리와 모듈화 설계
│   ├── 도메인 모델링과 불변식 보호
│   ├── 비동기 이벤트 기반 분산 설계
│   └── 다층 테스트 아키텍처와 통합 검증
│
├── .NET 백엔드 엔지니어링
│   ├── 클라우드 프린팅 모노레포 백엔드 및 API 게이트웨이
│   ├── 가계부 마이크로서비스 백엔드 및 BFF
│   ├── 비동기 OCR 및 AI 요약 파이프라인 백엔드
│   ├── 분산 애플리케이션 호스팅 및 관측성 표준화
│   └── 웹 API 공통 미들웨어 및 부트스트랩 계층
│
├── 클라우드 및 온프레미스 인프라
│   └── 하이브리드 Kubernetes 클러스터 구축 및 운영
│
├── DevOps 엔지니어링
│   └── 듀얼 사이트 GitOps 배포 및 재해복구 자동화
│
├── 개발자 경험
│   └── Roslyn 커스텀 정적 분석기 및 코드픽스
│
├── 하네스 엔지니어링
│   └── 멀티 코딩 에이전트 공통 규약 및 정적 가드
│
├── 웹 디자인 시스템
│   ├── 디자인 토큰 동기화 및 자체 Blazor 컴포넌트
│   └── 인터랙티브 웹 컴포넌트 갤러리
│
├── 모바일 애플리케이션
│   ├── Blazor Hybrid 크로스플랫폼 가계부 모바일 앱
│   ├── 모바일 라벨 편집기 앱 유지보수 및 SDK 34 현대화
│   └── 모바일 네이티브 인증·네비게이션·화면 인셋 추상화
│
├── Windows 데스크톱 애플리케이션
│   └── WYSIWYG 메모 인쇄 엔진 및 .NET 9 현대화
│
└── 시스템 프로그래밍
    ├── 크로스플랫폼 프린터 하드웨어 제어 통합 SDK
    ├── 5계층 크로스플랫폼 BLE 프로토콜 스택
    └── 멀티 플랫폼 USB 드라이버 추상화 라이브러리
```

| 시스템 프로그래밍 | 목차의 끝. 클라이언트 아래에서 하드웨어와 맞닿는 프린터 제어 SDK, BLE 프로토콜 스택, USB 드라이버 추상화를 다룬다. | 3 |
